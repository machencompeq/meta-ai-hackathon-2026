最後更新：2026-10-23（v0.1 為原始摘要）

## 1. 目的

每月關帳後，由一個 15 人的虛擬投資委員會，根據**我的帳本**與**當月台股數據**，產出一張「最終下單建議表」。下單權永遠在我（券商 App 手動下單）。

要解決的問題：
- 每月投資決策有固定流程、有理由、可回頭檢討，不憑感覺追高殺低。
- 融合多位大師的理念，但用台股的實際連動來落地。
- 檢驗委員會是否真的有幫助：長期要能贏過「全部買 0050」。

## 2. 與 v0.1 的主要差異

| 項目 | v0.1 | v0.2 |
|---|---|---|
| 執行環境 | 雲端聊天（手動貼資料） | **本機**（像 `/顧問`、`/記帳` 一樣的 skill），直接讀帳本重算結果；財務資料不上傳 |
| 團隊 | 4 位投資者 ＋ 首席平衡官 | 15 人：管理層 3、台股研究組 6、大師組 5、魔鬼代言人 1 |
| 閒錢 | 手動輸入 | 依帳本分配順序自動算（先卡費與預備金，才輪到投資） |
| 決策方式 | 辯論後由平衡官決定 | 四層決策：硬規則 → 可投資金額 → 核心 → 衛星；大師打分，總監可推翻但要寫理由 |
| 持股 | 未處理 | 每次會審都對現有持股做檢視卡 |
| 紀錄 | 無 | 每次會審存檔，1／3／6 個月後追蹤，與 0050 基準比較 |

## 4. 團隊（15 人）

### 4.1 管理層（3）

| 角色 | 職責 |
|---|---|
| **台股總監**（管理人） | 熟悉台股各種連動；派工、把大師理念翻成台股做法、串傳導鏈、提出 2～3 個方案、寫最終結論。可推翻大師表決（規則見 6.3） |
| **風控長** | 執行第 0 層硬規則；有否決權，總監也不能推翻 |
| **個人財務官**（會計師＋規劃師） | 從帳本算本月可投資金額、預備金階段、持股與回本價距離 |

### 4.2 台股研究組（6）— 每人只交一張訊號卡

| 角色 | 盯什麼 | 主要影響 |
|---|---|---|
| 總經與匯率 | 央行利率、新台幣匯率、美債殖利率、國發會景氣燈號 | 外資進出、高股息與金融股 |
| 半導體與科技供應鏈 | 費城半導體指數、台積電 ADR 溢價、AI 資本支出、IC 設計景氣 | 0050（台積電權重高）、科技個股 |
| 籌碼 | 三大法人、投信季底作帳、融資餘額、外資期貨未平倉 | 短期方向、市場溫度 |
| ETF 與存股 | 成分股調整、除權息、填息、殖利率、二代健保 | 0056、00878、0050 |
| 技術位階 | 季線、年線、量能、大盤離均線多遠 | 一次買或分批 |
| 中國與 A50 | 陸股政策、人民幣、陸股休市價差、槓桿每日重設的耗損 | 中國槓桿 ETF |

訊號卡格式：方向（偏多／中性／偏空）、強度 1～5、依據數據（**只能引用當月餵進來的數據**）、對我持股的影響。

### 4.3 大師組（5）— 只對總監的方案打分

| 角色 | 檢查什麼 |
|---|---|
| 巴菲特（價值） | 護城河、安全邊際、看不懂的不碰；對個股有否決權 |
| 彼得林區（成長） | 成長從哪來、PEG（本益比 ÷ 盈餘成長率）< 1、生活中看得到 |
| 柏格（指數） | 偏離大盤的理由、成本高低 |
| 達利歐（資產配置） | 整體配置與風險平衡、預備金是否足夠 |
| 科斯托蘭尼（投機） | 市場情緒與資金面、是否用閒錢、投機部位上限 |

每位大師的打分要有**可檢查的指標**（參考 ai-hedge-fund 的做法，例如股東權益報酬率、負債比、PEG、安全邊際），不能只用文字判斷。

### 4.4 制衡（1）

| 角色 | 職責 |
|---|---|
| 魔鬼代言人 | 專門攻擊最高分方案，防止所有人想法一樣 |

## 5. 台股連動（總監必須掌握）

總監要把訊號串成傳導鏈，至少涵蓋：

- **費半大跌** → 台積電 ADR 跌 → 隔天外資賣台積電 → 0050 跟跌 → 對定期買 0050 是加碼機會，不是賣訊號
- **美債殖利率升、台幣貶** → 外資匯出 → 權值股承壓；高股息與金融股受利率影響方向不同
- **0056 換股（6、12 月）** → 新納入成分股短期被買高 → 換股前不追
- **除息季（7、8 月）** → 0056／00878 配息入帳 → 照帳本規則記帳後再投入；單筆股利 ≥ 2 萬扣 2.11% 二代健保
- **月營收（每月 10 日前）** → IC 設計月營收年增率 → 林區評估 IC 設計個股的依據
- **季底投信作帳（3、6、9、12 月）** → 中小型股季底易被拉高 → 不追高
- **期貨結算（每月第三個週三）** → 結算前後波動大 → 避開下單
- **陸股休市、台股開盤** → 陸股相關 ETF 價格與淨值脫鉤 → 這幾天不交易

## 6. 決策規則

### 6.1 第 0 層：硬規則（風控長執行，任何人不能推翻）

1. 分配順序：卡費 → 本期應付 → 緊急預備金補到門檻 → 才可投資
2. **不賣股，除非翻正**（使用者 2026-10-23 決定）
3. 不加碼使用者標記的高風險持股（槓桿 ETF、單一個股）
4. 單一持股 ≤ 股票的 30%；槓桿 ETF ≤ 10%（只靠新資金稀釋達成，不靠賣）
5. 3 年內要用的錢（目標基金、學費）不進股市
6. 不融資、不當沖、不借錢投資

### 6.2 四層流程

| 層 | 誰 | 決定什麼 |
|---|---|---|
| 0 硬規則 | 風控長 | 能不能投、哪些標的被排除 |
| 1 可投資金額 | 財務官＋達利歐＋科斯托蘭尼 | 本月投多少；市場溫度決定一次買或分兩次 |
| 2 核心 | 柏格＋巴菲特＋存股派 | 0050／006208／0056／00878 選哪檔、比例 |
| 3 衛星 | 林區＋籌碼＋產業＋巴菲特把關 | 只有衛星比例 < 30% 才啟動；候選股 1～5 分，巴菲特可否決 |

### 6.3 計分與推翻

- 大師組 5 人對每個方案打 1～5 分，總分最高者勝；**同分選較保守者**（分散較高、成本較低）。
- 權重依預備金階段調整：

| 預備金階段 | 權重 |
|---|---|
| 未達階段 ① | 達利歐、柏格 ×1.5 |
| 階段 ①～② | 全部 ×1 |
| ≥ 階段 ② 且 衛星 < 30% | 林區、科斯托蘭尼 ×1.2 |

- **總監可推翻表決，但必須寫出理由**（使用者 2026-10-23 決定）；沒寫理由就照最高分方案。推翻時要寫：
  1. 推翻哪個方案、改選哪個
  2. 理由：必須引用某張訊號卡或某條傳導鏈
  3. 驗證條件：例如「3 個月後若不如原最高分方案，記為判斷錯誤」

## 7. 持股檢視卡（每次會審、每檔一張）

使用者 2026-10-23 決定：研究組要對現有持股發表意見。

| 欄位 | 內容 |
|---|---|
| 現價／回本價／還差多少 | 例：某檔 ETF 現價 X／回本價 Y／還差 +Z% |
| 占股票比例（上限） | 例：40%（10%） |
| 研究組訊號 | 相關組別的當月訊號 |
| 大師一句話 | 每位大師一句 |
| 狀態 | 持有／接近回本（差 5% 內）／到價（觸發減碼提案）／警示 |
| 警示條件 | 例：槓桿 ETF 耗損連續 3 個月擴大 → 提早檢查點 |

- 狀態再差，未翻正前都不會建議賣出。
- 到價時，總監提出減碼方案交大師表決，最後由我決定。
- 高風險持股可設定檢查點（例：半年後再評估）。

## 8. 會審紀錄與檢討

使用者 2026-10-23 決定：每次會審都要存檔。每份紀錄包含：

1. 輸入快照：當月財務數字、市場數據、資料日期
2. 6 張訊號卡、傳導鏈、2～3 個方案
3. 大師分數與理由；總監是否推翻與理由
4. 風控長檢查結果
5. 最終下單表（標的、零股股數、金額）＋「這個月不做什麼」
6. **我實際做了什麼**（有沒有照做、成交價），下單記帳時補填
7. 追蹤：1、3、6 個月後比較三者報酬
   - 實際選的方案
   - 原最高分方案（有推翻時）
   - 全部買 0050（基準）

若委員會長期贏不了「全部買 0050」，就簡化成只留柏格。

## 13. 未來部署：樹莓派＋財經龍蝦（OpenClaw）

構想：把委員會搬到一台 24 小時開著的小電腦上，讓「龍蝦」每天自動抓數據、每月自動開會、有警示時通知我。

### 13.1 硬體

- OpenClaw 官方文件：Raspberry Pi 4 或 5，RAM 2GB 以上（建議 4GB），64 位元系統（不能用 32 位元），16GB 以上 microSD 或 USB SSD。
- 樹莓派只當「閘道」：模型推理走雲端 API，不需要本機跑模型。
- Pi 5 負載下較熱，需要主動散熱；要跑會開子代理的 skill 時，Pi 5 比 Pi 4 合適。
- 另一個候選：**耐能 Kneo Pi**（Kneron，台灣）。2026-03-04 耐能官方部落格展示 Kneo Pi 跑 OpenClaw，定位是 24 小時背景執行、排程觸發、API 串接的小型節點。

| | Raspberry Pi 5（4GB） | Kneo Pi |
|---|---|---|
| OpenClaw | 官方文件支援（64 位元 Raspberry Pi OS） | 耐能官方展示整合；作業系統為 ArchLinux ARM |
| AI 加速 | 無 NPU | 自研 KDP NPU，INT8 約 4 eTOPS（INT4 7.2）；強項是影像辨識（官方稱 YOLO 約 2W、30 FPS 以上、可同時 4 路攝影機） |
| 本機跑大型語言模型 | 不適合 | 官方未說明；NPU 主要給影像模型，委員會的語言模型推理仍走雲端 |
| 擴充 | 40-pin GPIO | 40-pin GPIO，相容樹莓派感測器與螢幕；SD 卡 |
| RAM／價格 | 公開 | 搜尋未找到，需查官網或洽耐能 |
| 社群與教學 | 非常多 | 少 |

判斷：財經龍蝦主要是抓數據、排程、呼叫雲端模型，**NPU 幫助不大**；Pi 5 的文件與社群較完整，較適合第一台。Kneo Pi 若未來想加影像功能（例如拍收據自動記帳）才有優勢；購買前先確認 RAM 至少 4GB。

### 13.1b 分工構想

- 24 小時小主機：排程、每日抓數據、警示、存會審紀錄
- GPU 桌機（平常關機，由小主機喚醒）：跑本機開源權重模型、回測
- 研究組／大師組用較小模型；總監、風控說明、魔鬼代言人用推理最強的 Meta 模型

### 13.2 安全（最重要）

- 2026 年初 ClawHub（OpenClaw 技能市集）爆出大規模惡意 skill：資安業者統計上千個，多偽裝成**加密貨幣與交易工具**，會偷 SSH 金鑰、瀏覽器密碼、錢包資料。
- skill 沒有沙箱，安裝後可以讀檔案、連網路。官方已加 VirusTotal 掃描，但自稱「不是萬靈丹」。
